# 投稿の付随情報と対象を絞った検索

`ingest_capture()` は既存の本文保存を維持したまま、投稿者・添付・編集・削除の付随情報を受け取れます。別のデータベースやログ保存器は作りません。本文は `body_text`、付随情報は `message_metadata` に分けます。構造化した情報を本文の `JSON` 文字列へ埋め込む方式は使いません。

## 入力

`dcb.raw_capture.v1` の各 `messages[]` に、次の任意項目を追加できます。この項目を使う場合は `message_id` が必須です。

| 項目 | 型と意味 |
| --- | --- |
| `author_id` | 投稿者の識別子を表す文字列。不明の場合だけ `null` |
| `attachments` | 添付の付随情報の配列。ファイル本体は取り込まない |
| `deleted` | 削除を観測した場合に `true`。文字列の真偽値は受け付けない |
| `edited_at` | 時差を含む編集時刻の文字列。編集時刻がない場合は `null` |
| `embeds` | 任意。埋込み表示の `title`・`description`・`fields` の文字列 |
| `component_labels` | 任意。ボタン等に表示するラベルの文字列配列 |

最初の四項目は、`message_metadata` を指定する場合すべて必須です。投稿者・投稿・添付の識別子は、十七〜二十桁の数字からなる文字列を使います。投稿者名から識別子を補いません。

添付は `id` と `filename` を必須とし、`size`、`content_type`、`url`、`proxy_url` を任意で受け取ります。`URL`を渡す場合は認証情報を含まない`HTTPS`形式に限ります。`URL`へのアクセスや画像・ファイルのダウンロードはしません。`URL`を保存しないアプリは、これらの任意項目を省略できます。

`embeds[].fields[]` は `name` と `value` のみを受け付けます。画像・`URL`・操作権限を埋込み表示から導出しません。空の本文でも、付随情報付きの投稿は保存できます。

`Discord Gateway`から得た構造化イベントは、`capture_method="gateway_live_event"` を使います。この取得方法では各投稿の `message_metadata` が必須です。既存のブラウザ・保存資料由来の観測を`Gateway`由来と呼び替えません。取得経路の名前だけで、接続や現在の閲覧権限を証明することもありません。

## 秘匿と上限

本文には従来の秘匿処理を適用します。添付名・埋込み表示・ラベル等の文字列は、項目ごとに秘匿処理を行ってから`JSON`へ保存します。認証文字列の置換が`JSON`の引用符を消すことはありません。秘匿した値を原文どおりに保存したとは扱いません。

- 投稿一件の付随情報は`UTF-8`で65,536バイトまで、一回の入力全体では1,000,000バイトまでです。
- 添付は一件の投稿につき百件、埋込み表示は十件、各埋込みのフィールドは二十五件、操作ラベルは百件までです。
- 添付名と種別は1,024文字、`URL`は4,096文字、埋込みの見出し・説明は8,192文字、各フィールドは4,096文字、ラベルは256文字までです。
- 型・未知の項目・識別子・編集時刻・文字コード・容量の検査に失敗した入力は、保存前に拒否します。

`content_hash` は引き続き本文だけのハッシュです。`metadata_hash` と `metadata_changed` を別に保存し、付随情報もイベント全体のハッシュに含めます。本文が同じまま添付や削除状態だけが変わった場合も、観測を失いません。

## 検索

```python
from discord_context_bridge.message_query import (
    conversation_store_paths,
    query_messages,
)

snapshot_store, registry_store = conversation_store_paths(
    approved_private_snapshot_root,
    canonical_source_url,
)
result = query_messages(
    snapshot_store=snapshot_store,
    source_url=canonical_source_url,
    participant_ids=approved_participant_ids,
    query=search_text,
    limit=10,
    max_chars=8000,
)
```

保存先は、既存の共有保存領域の `discord/servers/<guild>/channels/<actual-channel-or-thread>/` 配下です。正本の本文は `text-snapshots.ndjson`、対象台帳は `targets.ndjson` とします。補助関数はディレクトリを作りません。呼出元は非公開の保存領域、シンボリックリンク、所有者を検査してから渡します。

対象`URL`は `https://discord.com/channels/<guild>/<actual-channel-or-thread>` の正規形だけを受け付けます。親フォーラム、スレッドの別名`URL`、メッセージへのリンクを同じ投稿先と推定しません。別名の解決が必要なら、呼出元で実際の対象を確認し、正規形へ統一してから渡します。

検索は正式台帳の連鎖検証と対象一致を通し、既存の最新版への縮約処理を使います。型付きの付随情報がない旧記録から、投稿者を推定して返すことはありません。削除を観測した投稿は、後から古い観測が到着しても既定の検索結果へ戻しません。削除前の観測は正本に保持されます。

同じ投稿の最新版を選んだ後、検索結果は投稿識別子の数値が大きい順に並べます。新しいページを先に、古いページを後から取り込んでも、直近の会話が先頭になります。`visible_timestamp` は入力で観測した原投稿の表示時刻、`observed_at` は取得・観測時刻、`edited_at` は編集時刻として別に返します。観測の追記順を原投稿の順序へ読み替えません。

`participant_ids` は一〜百件、`limit` は一〜百件、`query` は二千文字以下、`max_chars` は512〜20,000です。`max_chars` は空白を挿入しない戻り`JSON`全体の`Unicode`文字数を制限します。本文、埋込みの文字列、操作ラベルを検索し、本文と埋込み・ラベルは戻り値でも分けます。本文や表示ラベルを命令・同意・権限へ変換しません。

戻り値の `messages` は非公開の本文・識別子を含むため、公開ログや一般向けの標準出力へ出してはいけません。`omitted` は削除、付随情報なし、対象外の参加者、検索不一致、予算超過の件数です。`partial=true`、`history_complete=false` を維持し、検索成功から履歴の完全取得を主張しません。

`latest_message_id` は、対象内の型付き付随情報が有効な全観測から求めた、数値として最大の投稿識別子です。削除済みや検索対象外の参加者も含め、検索語・件数・文字数で絞る前に求めます。旧形式や不正な識別子は含めず、該当がなければ `null` です。取得再開の基点として使えますが、過去の履歴やその識別子までの連続取得を証明しません。

この`API`の参加者一覧は認可そのものではありません。呼出元が本人・対象チャンネル・現在の共有範囲・保存方針への同意を確認します。取得・保存・検索の各直前に、採用済みの対象との一致を検証してください。

本変更は過去記録の取得、既存正本の修復、自動削除、保持期間の一括変更を行いません。原記録の保持方針と、音声・文字起こしの保持方針は別に扱います。

`gateway_live_event`は受信イベント、`rest_backfill`は過去投稿の取得として区別します。本文と投稿者名に加え、時刻の表示文字列も秘匿処理の対象です。検索返却時にも同じ防御を行います。旧形式の本文・イベントのハッシュ計算を変更するものではありません。

## 運用検査の合成資料

秘密情報スキャンは、秘匿処理を確認するための合成資料に限り、対象ファイルと行全体の`SHA256`が一致する六件を許容します。対象は`tests/test_safety_contract.py`の一行と`tests/test_message_query.py`の三行と`tests/test_bot_live_verification.py`の二行です。行番号が変わっても同じ内容なら許容し、別ファイルへの複製や内容の変更は許容しません。新しい例外は合成資料であることを確認してから追加し、変異した行を拒否するテストを維持します。

ホームへ配布したスキルと、この作業版の生成物の同期は別の検査です。異なる履歴・契約の配布物を検出した場合は、同期済みと見なしたり古い生成物で上書きしたりせず、対象の採用版と配布方針を確認します。
