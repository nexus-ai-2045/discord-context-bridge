# 決定記録 0005: フォーラムのスレッドは実際の `thread_id` ごとの台帳へ保存する

## 状態

採用

## 来歴

2026-09-01 に、このリポジトリの外の非公開の決定記録で採用された判断を、実装するこのリポジトリの中へ移した。公開できる形に書き直した。この判断は、フォーラムの親の下に入れ子で保存するという、それ以前の判断を置き換えたもの。

## 背景

以前は、フォーラムの親チャンネルの下にスレッドを入れ子で保存すると決めていた。しかし 2026-09-01 に測り直すと、入れ子の保存は0件で、実際の `thread_id` ごとの平らな保存が279件あった。取得の実行も確認の仕組みも、平らな保存へ収束していた。

内部ブラウザと `Chrome` では、同じスレッドの `URL` の形が違う。親チャンネルを本文の保存の鍵に使うと、同じスレッドが複数の正本に分かれてしまう。

## 決定

1. フォーラムのスレッドの生の記録の正本は、実際の `thread_id` ごとの次の台帳とする。
   ```
   channels/<thread_id>/text-snapshots.ndjson
   ```
2. 内部ブラウザの `/channels/<server>/<forum>/threads/<thread>` と、`Chrome` の `/channels/<server>/<thread>` は、同じスレッドの別名として、実際の `thread_id` の台帳へ解決する。発言への直接のリンクは別名に含めない。
3. `parent_channel_id`、表示順、公開・非公開・保管・ロックの状態、ページ送りは、親の一覧と索引で持つ。本文の保存の鍵には使わない。
4. フォーラムの直下に、まとめた本文の台帳を置かない。フォーラムのフォルダは、一覧と完全さの証拠だけにする。
5. 取得の締めくくりでは、予定した一覧、終了の受領、途中の状態、実際のスレッドの台帳の本文の指紋と出来事の指紋の連鎖を突き合わせる。欠け、失敗、旧形式だけの分があれば失敗として止め、「全部取得した」と名乗らない。
6. 取得の進行は、時間での巡回ではなく、完了を表す出来事（成果物の準備完了、受領、生産側の停止、ゲートの結果など）で次の状態へ進める。時間切れは購読が切れたことの検知だけに使い、完了の判定には使わない。
7. 一覧の `global_index` は0始まりとし、準備が済んだ成果物の対象は `inventory[global_index]` と一致しなければならない。受領の本文の指紋があっても、この結び付きが違えば完了の証拠に数えない。
8. 締めくくりには、全ての生産側の終了の出来事、`DCB` の作成専用の受領、書き換えできない停止の受領、厳格なゲートの受領を必須とする。無通信や書き換えできる状態は、停止の証拠に使わない。
9. 期待する生産側の集合は、出来事の自己申告ではなく実行の構成から導き、各受領を同じ実行の定義の指紋へ結び付ける。

## 退けた案

- 279件を入れ子の保存へ移し、確認の仕組みをフォーラム対応にする案は、既存の証拠の大量移動と分岐が増えるため棄却した。
- フォーラムの直下にまとめる案は、スレッドの粒度を失うため引き続き棄却する。

## 影響

良い影響:

- スレッドの粒度を保ったまま、内部ブラウザ、`Chrome`、確認の仕組み、`DCB` の保存先が一致する。
- 親の一覧と生の本文の責務が分かれ、親の `URL` を本文の正本と取り違えない。

トレードオフ:

- フォルダの構造だけではフォーラムの親子関係を読めないため、一覧と索引の検査が必須になる。

## 関連

- 決定記録 0006 は、この台帳を `DCB` の記録全体の正本とする。
