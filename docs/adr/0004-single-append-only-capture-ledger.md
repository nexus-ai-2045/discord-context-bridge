# 決定記録 0004: 取得した記録は追記専用の台帳へ集め、読み物は台帳から作り直す

## 状態

採用。正本とする台帳の場所（決定1）は 決定記録 0006 で置き換えた。ほかの項目は有効。

## 来歴

2026-07-25 に、このリポジトリの外の非公開の決定記録で採用された判断を、実装するこのリポジトリの中へ移した。公開できる形に書き直し、外の資料への参照は外した。

## 背景

取得した記録の保存先が7系統に分かれ、記録の形式は15種類以上、形式名の項目の名前まで3通りに分かれていた。判断に効く事実は次のとおり。

1. 正本は決まっていたのに使われていなかった。決まりでは `text-snapshots.ndjson` を追記専用の正本とし、`MCP` の道具はすべてこの経路を読んでいた。分かれた主な原因は、リポジトリにコードの無い直書きの成果物が、正規の経路を迂回して溜まったことだった。
2. 正本自体にも欠陥があった。記録は「チャンネルの見えている文字の塊」で、投稿者と時刻が本文に埋もれ、発言単位になっていなかった。
3. 対象の鍵から元をたどる台帳が無かった。鍵の作り方が4通り並存していた。
4. 重複の除き方が経路ごとに違い、添付の三重の写しや、同じスレッドの5世代の取り直しが実在した。

## 決定

### 決定1: 正本は追記専用の台帳1本にする

- 決まりにある追記専用の台帳（`event_id` / `stream_id` / `stream_sequence` / `content_hash` / `event_hash` の連鎖）を唯一の正本とする。新しい保存先は作らない。
- 直書きされていた各取得の形（範囲指定、差分、`URL` 直接、途中保存など）は、台帳の `event_type` で表す。
- 発言単位に構造化できた取得は発言単位の記録として、見えている文字の塊しか取れない取得は塊の記録として、どちらも同じ台帳へ追記する。

この決定1の「どの台帳を正本とするか」は 決定記録 0006 で置き換えた。

### 決定2: 発言単位に正規化した読み物の層を設ける

- 台帳の記録を取り込みの層で発言単位に正規化した読み物を、作り直せる形で持つ。
- 投稿者が分からない時は作らず、`author=null` と `author_resolution=unknown` で残す。
- 重複を除く鍵は、`message_id` があれば `(target_key, message_id)`、無ければ正規化した本文の `content_hash` とする。台帳は追記を続け、重複は読み物の側で除く（重複は保存を止める理由ではなく、印を付けるだけにする）。

### 決定3: 対象の台帳を設ける

- 対象の台帳（追記専用）に、対象の鍵、`URL`、表示名、別名、初めて見た時刻を持たせる。
- 正規の鍵は `sha256(url)[:16]` とする。ほかの作り方の鍵は別名として登録し、新しく発行しない。
- 対象の台帳は手元の非公開の領域に置き、表示には安全な名前だけを出す。

### 決定4: 書込みの経路を機械的に強制する

- 取得した記録は取り込みのコマンドだけで保存し、ファイルへの直書きを禁止する。
- `lint_capture_store_layout.py` で、許可していない場所への新しいファイル、形式名の項目の不統一、登録していない形式を検出し、`ops_check.py` に組み込む。

### 決定5: 既存の成果物は凍結して取り込み直す（消さない）

- 既存の直書きの成果物は `archive/` の下へ移して読み取り専用で凍結し、書き換えも削除もしない。
- 形式ごとの変換を通して台帳へ取り込み直す。入力の行数が、取り込んだ件数と理由付きで除外した件数の合計に一致することを、移行の完了条件とする。
- 手元の生の記録と、`Obsidian` 向けの読み物は、台帳から作り直す読み物として位置づけ直す。

## 影響

良い影響:

- 「どこに何があるか」を台帳と対象の台帳で答えられる。
- 重複は読み物の側で消え、増える容量は凍結分だけになる。
- 台帳は書き換えないので、正規化の誤りは、変換を直して読み物を作り直せば直せる。

トレードオフ:

- 直書きの自由度が下がり、取り込みのコマンドの整備が前提になる。
- 形式ごとの変換を多数実装する必要がある。
