# 決定記録 0003: 取得済みの記録の鮮度は実測し、手元の最新を本当の最新と断定しない

## 状態

採用

## 来歴

2026-06-29 に、このリポジトリの外の非公開の決定記録で採用された判断を、実装するこのリポジトリの中へ移した。中身は変えず、公開できる形に書き直した。

## 背景

`Discord` の `URL` を確認する時、`Discord` のデスクトップアプリの手元の記録を情報源にすると、その中の最新の発言を「そのチャンネルの本当の最新」と取り違える事故が起きた。実際に、本当の最新が 11:11 なのに、手元の記録は 00:37 を最新として返した例がある。

手元の記録全体の更新時刻が新しくても、そのチャンネルが取り直された保証はない。「最新がいつか」は測れる事実であり、測らずに断定してはいけない。

## 決定

1. `Discord` の `URL` を確認した結果には、鮮度の4項目を必ず含める。
   - `cache_newest`: 手元の記録の中で最新の発言の時刻と投稿者
   - `now_gap_h`: 現在との差（時間）
   - `cache_sync_hint`: 手元の記録の最終書込み時刻。参考値であり、全体の更新時刻はチャンネルごとの取り直しを保証しないことも明記する
   - `freshness_verdict`: `confirmed`（実際の画面を1回確かめて本当の最新を確定した）または `unconfirmed`（手元の記録だけ。`cache_newest` は確かめていない最新と明示する）
2. `unconfirmed` のまま「最新」と断定しない。新着の判断や返信の要否のように確証が要る場面では、実際の画面を1回確かめて確定する。
3. 古い取得をあとから保存した記録は、保存した時刻ではなく、元の取得時刻（タイムゾーンが付いている時だけ）で鮮度を判定する。

## 退けた案

- 手元の記録の最新をそのまま最新として返す案は、取り違えの実例があるため棄却した。
- 毎回実際の画面から取る案は、手間が大きすぎるため、確証が要る場面だけに限定した。

## 影響

良い影響:

- 古い手元の記録による「最新」の取り違えを防げる。
- 鮮度が `confirmed` と `unconfirmed` で見えるようになる。

トレードオフ:

- 確認の結果が長くなる。
- 確証が要る場面では、実際の画面を1回見る手間が増える。

## 関連

- 決定記録 0005（スレッドごとの保存）は、同じ `Discord` の記録の運用に関わる。
