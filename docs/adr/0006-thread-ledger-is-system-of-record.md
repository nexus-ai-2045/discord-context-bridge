# 決定記録 0006: 記録の正本はスレッドごとの台帳とし、回答と読み物はそこを読む

## 状態

採用。決定記録 0004 の 決定1（どの台帳を正本とするか）を置き換える。

## 背景

2026-11-20 に、手元の記録の置き場を件数だけで測った。記録は3か所に分かれていた。

| 置き場 | 件数 | 中身 | 読んでいる物 |
|---|---|---|---|
| 共有の台帳（`text-snapshots.ndjson` 1本） | 約2,100件 | ほぼすべてが見えている範囲の文字の塊（1件の長さの中央値は約7,500文字） | `MCP` の回答の道具、`knowledge-wiki` |
| スレッドごとの台帳（決定記録 0005） | 405ファイル、約33,000件 | 大半が発言単位の記録 | `URL` の取り込みの入口の1コマンドだけ |
| 全文の取得の置き場 | 34件の取得 | 発言番号つきの出来事の台帳 | どれも読んでいない |

共有の台帳とスレッドごとの台帳の重なりは0件だった。一番大きく新しい記録の束を、回答も読み物も見ていなかった。決定記録 0004 は「台帳1本」を正本と決めたが、その後の 決定記録 0005 でスレッドごとの台帳が正本になり、両者の関係が決まっていなかった。

また、見えている範囲の塊と全文の取得の発言では単位が違うため、本文の指紋で重複を見分けることはできない。

## 決定

1. 記録の正本は、決定記録 0005 のスレッドごとの台帳とする。決定記録 0004 の 決定1 が定めた「共有の台帳1本」を置き換える。決定記録 0004 のほかの項目（追記専用、読み物は作り直す、書込みの経路の強制、凍結して取り込み直す）は、このスレッドごとの台帳に当てはめる。
2. `MCP` の回答の道具と `knowledge-wiki` の読み物は、スレッドごとの台帳を読む。共有の台帳の既存の記録も、読む対象に含める。
3. 全文の取得の結果は、発言番号つきの発言単位の記録（`message_observation`）として、スレッドごとの台帳へ追記する。
4. 同じ対象に全文の取得の記録がある時、読み物と回答は、その対象の見えている範囲の塊を使わない。発言単位の記録は `(target_key, message_id)` で重複を除く。
5. 全文の取得の記録は `URL` を持たず、対象の指紋の作り方も台帳の対象の鍵と違う。合流の前に、両者の対応を取る。対応が取れない取得は合流させず、理由付きで除外の件数に数える。

## 未決

- 合流を今ある取得について一度だけ行うか、今後の取得のたびに自動で行うか。
- 共有の台帳への新しい書込みを止め、書込み先をスレッドごとの台帳へ寄せるか。

## 退けた案

- 共有の台帳を正本のままにし、スレッドごとの台帳の約33,000件をそこへ写す案は、データを二重に持ち、決定記録 0005 と食い違うため棄却した。
- 置き場を分けたまま、読む側が全部を読む案は、正本が複数になるため棄却した。
- 本文の指紋で塊と発言の重複を除く案は、単位が違って成り立たないため棄却した。

## 影響

良い影響:

- 回答と読み物が、発言単位の記録の大半と全文の取得を使えるようになる。
- スレッドの保存と記録の正本が一致し、置き場の説明が1つになる。

トレードオフ:

- 回答の道具と読み物の作成の両方で、読む場所を変える実装が要る。
- 対象の鍵の対応表を作る作業が先に要る。
- 台帳は追記専用なので、誤って合流させた記録は取り消しの記録で打ち消すことになる。そのため、本番の台帳への合流は、試し実行と件数の照合を通してから行う。
